# Limitations

- **Painter's algorithm**: props that intersect each other cannot resolve per
  voxel. Two overlapping stacks draw in `priority` order.
- **No occlusion culling.** `SpriteStackScene` culls behind-camera, off-canvas
  and sub-pixel props, but a prop fully hidden behind another is still drawn —
  that would need a depth buffer.
- **No per-voxel lighting or reflections.** The built-in shadow is a flat
  projected ground shadow; shading has to be baked into the slices — the carving
  script does that with `--shade`.
- **Uniform slices only**: `sliceCount` must match the asset and divide its width
  exactly.
- A very large `scale` plus many slices costs fill rate; cache or pre-bake if it
  shows up in a profile.
- **Animation is frame based.** `SpriteStackAnimation` swaps whole atlas rows.
  `StackMotion` adds per-slice sway and lean, but there is no cloth simulation,
  no per-slice twist and no crossfade between clips. Blending two animations
  means drawing both with an opacity.
- **Motion quantises to art pixels in the software rasterizer**, because the
  buffer is 1x. That matches the pixel grid; if you need sub-pixel motion at a
  high display scale, move the component instead of the slices.
- **Slice cuts hide whole slices.** There is no per-slice opacity: the slice at
  the frontier is dissolved with a 4×4 Bayer dither. Cutaways are per stack, so
  the interior has to exist in the strip — the engine cannot invent a room.
- **`roll` is a 2D drawing effect.** It rotates the finished sprite around
  `rollPivot`, like the pitch squash, so it cannot reveal a side the current
  `yaw` does not show. A true 3D roll would need the volume re-sliced along
  tilted planes, which voxelises and loses the pixel-art edges.
- **Collision is a box on the ground plane.** The proxy is the volume's tight
  bounds projected down, so an L-shaped or diagonal prop collides as one
  rectangle and can block empty corners. Add a smaller explicit `size` for a
  better fit. There are no slopes, ramps, step-up onto props or vertical
  movement — `stepHeight` only ignores short bodies entirely.
- **Slice LOD drops thin features along with the slices.** It only skips
  cross-sections that land under a device pixel, so a silhouette (the union of
  overlapping slices) barely moves — but a one-pixel detail that exists on a
  single skipped slice, like a gap under a railing, can disappear. Raise
  `sliceLodPixels` only if you can live with that; set `sliceLod = false` or
  `object.sliceStep = 1` for a hero prop whose tiny details matter.
- **Only the moved circle collides.** Props never push each other; `scene.move`
  tests one circle against every blocking body. Player-vs-player needs a second
  circle test with `blocks`.
- **`SpriteStack.fromImage` cannot derive a footprint**, because it has no raw
  pixels to read. Give it an explicit `SpriteStackCollider.size` (and `height`
  if `stepHeight` matters) instead.
