# Performance

- The software rasterizer renders into a 1x art-pixel buffer with nearest
  inverse sampling, then draws the opaque pixels grouped by color as integer
  squares. Cost scales with the prop's on-screen footprint, not the slice
  count, so 16-slice and 43-slice props cost about the same.
- The `fromImage` fallback keeps the old per-slice `drawImageRect` path (one
  draw per slice, plus four outline passes when enabled).
- Every `render` call rebuilds the art-pixel buffer, the occupancy mask and
  the per-color point lists, so a whole scene of props is CPU-bound. Bake what
  does not change: `stack.bake(...)` records a `Picture` and replaying it is a
  single `drawPicture`. `SpriteStackTurntable` does that per yaw bucket and
  `warmUp()` pays the cost up front.
- Cache the `SpriteStack` (and therefore the `ui.Image` and its RGBA buffer)
  per asset with `SpriteStackCache`, not per instance.
- `pixelSnap` rounds the ground anchor to whole pixels; keep it on for moving
  props, otherwise the upscaled grid shimmers.
- Keep `scale` at an integer value and filtering at nearest for crisp pixels.
- Y-sort whole stacks by their ground point; never interleave slices of two
  props.
- **Cull before you render.** `SpriteStackScene` skips props behind the near
  plane, props whose projected bounds miss the canvas and props smaller than
  `minimumProjectedPixels` (default `0.5` px) before they reach
  `SpriteStack.render`. `scene.stats` exposes the split — read `drawn` against
  `total` when a scene feels heavy. There is no occlusion culling: a prop fully
  hidden behind another is still drawn.
- **`roll` costs the same as no roll.** It is one `canvas.rotate` around the
  pivot before the stack is rasterised, not an extra pass, and `boundsFor`
  returns the rotated envelope so culling stays exact. Because the art-pixel
  squares are no longer axis-aligned at fractional angles, edges are resampled
  slightly; the pixel grid is crispest at `roll == 0`.
- **Collision is cheap and lazy.** The expensive part — rebuilding the stack
  volume — happens once per object and is cached; `scene.collisionBodies()`
  afterwards only costs a few products per blocking prop. `scene.move` first
  rejects the whole sweep against the bodies' world AABBs and only then runs
  substeps, so walking in open space allocates nothing per body and does one
  pass. Keep `maxSubsteps` as low as your fastest movement allows.
- **Detail tiers.** Ink and shadow are each a full sweep of the rasterizer's
  buffer, and below a few pixels they read as a blot rather than detail.
  `outlineMinimumPixels` and `shadowMinimumPixels` skip them when a prop is
  smaller than the floor on **both** axes; `drawOutlines` / `drawShadows` turn
  a pass off for the whole scene. `SpriteStackSceneDetail.balanced` is a safe
  starting point.
- **Slice LOD.** A prop drawn at a projected scale below `1` puts consecutive
  cross-sections closer together than a device pixel, and the downscale merges
  them anyway. `scene.sliceLod` (on by default) then draws every `N`th slice,
  each one still at its true height, so the silhouette does not move and the
  rasterizer skips work the screen could not show. Drawn slices stay within
  `sliceLodPixels` device pixels of each other (default `1`); `sliceLod: false`
  restores the full render, and `SpriteStackSceneObject.sliceStep` overrides the
  choice for one prop. `scene.stats.slicesDrawn` against `slicesTotal` (and
  `sliceLodSaving`) shows what it saved. Measured on CI with 60 props at scale
  `0.22`: see the benchmark output.
- **A still scene pays almost nothing.** `scene.cacheStillFrames = true`
  records the frame once and replays a `Picture` while every input stays the
  same. The key covers the camera, the canvas size, the sky, the ground, every
  field of every object and the detail switches; a moving scene pays only the
  hash, and a still one skips the rasterizer entirely.
- **The governor.** `SpriteStackQualityGovernor` reads frame gaps and returns
  a `SpriteStackSceneDetail` when the level should move. It judges two-second
  windows (median frame and the share of long ones), waits for the camera to
  move before applying a change so it does not pop, drops two levels at once
  when frames are crawling, and backs off exponentially after a level-up
  proves slow. It is pure Dart: feed it the gaps from your ticker and call
  `scene.applyDetail` when it returns one.
