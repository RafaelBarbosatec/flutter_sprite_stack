# 3D Scene

`SpriteStackScene` places props in a world with a perspective camera. It is
engine-free: it only needs a `Canvas`, and it draws every prop with the same
`SpriteStack.render` you already use — just with a `yaw`, a scale and a screen
position derived from the camera.

The scene does **not** draw a mesh. It projects each prop's footprint centre,
derives the sprite yaw and pitch from the camera-to-prop vector, scales by depth
and paints far to near. Props are **world-aligned by default**, so they follow
the projected ground grid and read as fixed objects on the map while the camera
moves — orbiting reveals every side of their cross-sections.

`position` is the point the prop stands on: the scene pivots the sprite on the
centre of its opaque footprint (`SpriteStackAnchor.footprintCentre`), not on the
edge facing the camera, and a `collider` is centred on the same point. That is
what keeps the pixels inside the collision box when the camera orbits. The
`anchor` option on `SpriteStack.render` itself still defaults to the classic
`bottomCentre`, so a plain sprite outside a scene is unaffected.

**Yaw and squash come from the projection, not just from the ray to the prop.**
A perspective ground plane does not keep its lines parallel: away from the
centre of the frame they turn towards their vanishing points. The scene solves
the local Jacobian of the projection at each prop for the `yaw` and squash that
make the sprite's footprint edges parallel to the projected ones — otherwise a
house in the corner of the view sits a few degrees twisted inside its own
collision box. On the optical axis this reduces to the camera-to-prop azimuth
and `sin(pitch)`.

## A minimal scene

```dart
final scene = SpriteStackScene(
  camera: SpriteStackCamera.orbit(yaw: 0.8, pitch: 0.6, distance: 900),
  zoom: 2.4,                       // art pixels per world unit at the target
  sky: const SpriteStackSky(
    top: Color(0xFF070D16),
    horizon: Color(0xFF27435E),
    bottom: Color(0xFF16232F),     // matches the ground's fadeColor
  ),
  ground: const SpriteStackGround(
    extent: 700,
    step: 70,
    cellSize: 70,
    checker: [Color(0xFF142430), Color(0xFF1D303D)],
    fadeColor: Color(0xFF16232F),
    fadeDistance: 2400,
  ),
  objects: [
    SpriteStackSceneObject(
      stack: house,
      position: const SpriteStackPoint(-230, -40, 0), // x, y, z (z is up)
      yaw: 0.5,
    ),
  ],
);
```

Paint it once per frame from a `Ticker` + `CustomPainter`:

```dart
scene.camera.yaw += dt * 0.2;
scene.paint(canvas, size);
```

## World units

One world unit is one source art pixel, so a 48 px wide house is 48 units wide
and `z` is up. `zoom` is the scale at the camera's target plane; objects closer
to the camera grow. Keep `zoom` an integer multiple of your pixel scale when you
want crisp pixels.

## World-aligned props and billboards

`SpriteStackSceneObject.billboard` decides how `yaw` is interpreted:

| `billboard` | `yaw` means | Use for |
| --- | --- | --- |
| `false` (default) | A rotation **in the world**. The scene derives the visible sprite yaw and pitch from the camera-to-prop vector, so the prop turns with the ground plane as the camera orbits or follows | Houses, trees, vehicles that turn with their heading |
| `true` | A fixed **screen-space** angle. The camera orbit does not rotate the prop at all | Stylised scenery that must keep one facing in a fly-over |

World-aligned is the safe default: it keeps props consistent with the painted
ground cells, which are themselves projected. A prop that must not spin on
screen — a billboard in the classic 2.5D sense — opts in with `billboard: true`.

```dart
SpriteStackSceneObject(
  stack: house,
  position: const SpriteStackPoint(-230, -40, 0),
  yaw: 0.5,              // world rotation (default: billboard false)
);

SpriteStackSceneObject(
  stack: sign,
  position: const SpriteStackPoint(120, 60, 0),
  yaw: 0.1,              // fixed screen facing, ignores the camera
  billboard: true,
);
```

## Camera

`SpriteStackCamera.orbit(yaw:, pitch:, distance:, target:)` puts the camera on a
sphere around `target`. `pitch` is clamped just short of top-down so the camera
never gimbal-locks.

| Member | Meaning |
| --- | --- |
| `camera.yaw` / `camera.pitch` / `camera.distance` | Free to mutate every frame |
| `camera.target` | World point the camera looks at |
| `scene.projectObject(object, size)` | Screen footprint centre, depth, scale, render yaw, render pitch and bounds |
| `scene.horizonY(size)` | Screen y of the horizon; can fall outside the canvas |

## Sky and horizon

`SpriteStackSky` paints a vertical gradient behind everything, anchored to the
horizon — the vanishing line of the ground plane, the same line
`scene.horizonY(size)` reports. It follows the camera pitch, so orbiting leaves
it still and only tilting moves it. Above the horizon it blends `top` →
`horizon`; below it, `bottom` shows wherever the ground does not reach.

Set the ground's `fadeColor` to `bottom` so distant cells dissolve into the
backdrop instead of ending on a hard edge. `horizonFraction` pins the horizon to
a fraction of the canvas instead of deriving it from the camera.

With this projection the horizon only enters the frame at a shallow pitch: a
top-down-ish orbit fills the screen with ground, and there is no sky to see.

## Painting the ground

The floor is drawn as projected cells clipped against the near plane:

| Parameter | Meaning |
| --- | --- |
| `fill` | Solid base color for every cell |
| `checker` | Two colors alternating by `(ix + iy)` |
| `colorAt(x, y)` | Color per cell centre, for procedural floors. Called only for cells that survive the near-plane and off-canvas reject |
| `fadeColor` + `fadeDistance` | Blend distant cells into the horizon |
| `step: 0` | Hides the grid lines |
| `cellSize` | Size of each painted cell, world units |

Cells are flat colors, not textures — a texture would need subdivision or a
textured rasterizer to be perspective-correct.

## Sorting

Sorting is per object (painter's algorithm) by the depth of the ground point, so
two intersecting props cannot resolve per pixel. The volume/mesh is not drawn;
`SpriteStackCollider` uses the volume for collision (see below), and
`SpriteStackMesher` is available when you need the exact geometry.

## Collision

Give a prop a `collider` and it blocks movement; leave it `null` and it stays
walk-through scenery. The proxy is a **box on the ground plane**, sized from the
stack volume by default — collision never reads sprite pixels, so a transparent
margin in the art does not make a prop passable, and the result does not change
with the yaw the camera happens to pick.

```dart
final house = SpriteStackSceneObject(
  stack: houseStack,
  position: const SpriteStackPoint(120, 40, 0),
  collider: const SpriteStackCollider(),
);

final result = scene.move(
  player.position,
  delta: Offset(vx * dt, vy * dt),
  radius: 12,          // the character's ground radius, world units
  ignore: player,      // do not collide with yourself
);
player.position = result.position;

if (result.collided) {
  // result.hits holds the bodies that pushed the character out.
}
```

`move` sweeps the movement in substeps no longer than `radius`, and each substep
is pushed out along the contact normal. That is what makes a diagonal move into
a wall **slide**: the normal component is removed and the tangent survives.
`stepHeight` ignores bodies no taller than it, so a low curb can be walked over.
`maxSubsteps` (default `32`) caps the cost; a single frame can cover
`32 × radius` world units without tunnelling.

`blocks(position, radius: 12)` is the same test without moving, useful for
spawn checks and "can I interact from here?".

### Where the footprint comes from

`SpriteStackCollider()` derives the footprint from `stack.toVolume()`: the tight
bounds of the solid voxels in the ground plane, plus `padding`. The volume also
gives the proxy height, used only by `stepHeight`. It is built once per object
and cached, so querying every frame does not re-scan the atlas.

Stacks built with `SpriteStack.fromImage` have no raw pixels to read. Give them
an explicit box instead:

```dart
SpriteStackSceneObject(
  stack: house,
  position: const SpriteStackPoint(120, 40, 0),
  collider: const SpriteStackCollider(
    size: Size(40, 30),   // art px: width x slice depth
    height: 29,           // art px above the ground
    padding: 2,
  ),
)
```

Lengths are in art pixels and scale with `object.scale`, so the same collider
works at any prop size. The box is centred on `object.position`; `offset` shifts
it in the prop's local frame (`+y` is the prop's forward), which is the escape
hatch for art whose solid part is not centred in the strip.

Because the sprite is pivoted on the same footprint centre, the drawn prop stays
inside its box while the camera orbits. `paintCollisionDebug` is the quickest
way to confirm that on your own assets.

The box rotates with `object.yaw`, so turning a prop turns its footprint.

### Seeing the proxy

`paintCollisionDebug` draws the resolved boxes over the scene: the same oriented
box `move` uses, projected back to the screen, with a post at each corner for
the height. Call it right after `paint`, with the same canvas and size.

```dart
@override
void paint(Canvas canvas, Size size) {
  scene.paint(canvas, size);
  if (!debug) return;
  scene.paintCollisionDebug(
    canvas,
    size,
    ignore: player,          // do not outline the character as a blocker
    circle: player.position, // the sweep circle, as 24 projected segments
    circleRadius: 12,
    stepHeight: 6,           // bodies below this show in orange
  );
}
```

Colours, stroke width and the posts are parameters, so the overlay can match
your palette. Objects without a collider draw nothing. It rebuilds the bodies
on every call — leave it behind a debug flag.

### What it does not do

Collision is confined to the ground plane: there are no slopes, ramps or
vertical movement, and a body is either blocking or not. Props do not collide
with each other — only the circle you pass to `move` is tested. Two props with
overlapping footprints simply overlap; `maxSubsteps` and the resolution passes
settle a character between them without pushing the props apart.

## Following a moving prop

`SpriteStackFollowCamera` aims at a point `lookAhead` units in front of a
subject and swings the camera yaw towards the subject's facing, both with
exponential, frame-rate independent smoothing
(`1 - exp(-rate * dt)`; a rate of `3` is roughly a 330 ms time constant).

```dart
final follow = SpriteStackFollowCamera(lookAhead: 60, yawRate: 3);

// per frame
follow.update(scene.camera, subject: car.position, yaw: car.yaw,
    velocity: velocity, dt: dt);
```

The lag is the point. The subject is world-aligned (the default), so the scene
derives its sprite yaw from the camera-to-prop vector: a camera that copied the
car's yaw instantly would keep that difference at zero and the car would never
appear to rotate — the world would just spin around a locked sprite. Trailing
the subject by a fraction of a second exposes the turn. `distance` and `pitch`
stay in the caller's hands.

| Parameter | Default | Meaning |
| --- | --- | --- |
| `positionRate` | `6` | How fast the target chases the subject, per second |
| `yawRate` | `3` | How fast the camera yaw follows the subject, per second |
| `lookAhead` | `60` | Aim point ahead of the subject, along its velocity |
| `height` | `25` | Height above the subject the camera aims at |
| `deadZone` | `0` | Radius inside which the target does not move |

Two statics help you animate a subject yourself:
`SpriteStackFollowCamera.forwardOf(yaw)` returns the world direction a prop
faces (front is `+Y`, so `yaw = atan2(vy, vx) - pi / 2` for a velocity), and
`approachAngle(from, to, factor)` turns by the shortest arc.

## Culling and stats

Props behind the near plane, props whose projected bounds miss the canvas and
props smaller than `minimumProjectedPixels` (default `0.5`) never reach
`SpriteStack.render`. `scene.stats` reports what happened after each `paint`:

| Field | Meaning |
| --- | --- |
| `drawn` | Props that actually rendered |
| `culled` | Props whose projected bounds missed the canvas |
| `behindCamera` | Props behind the near plane |
| `tooSmall` | Props below `minimumProjectedPixels` |

That is the number to watch when a scene gets heavy. There is no occlusion
culling: a prop hidden behind another is still drawn.

```dart
scene.minimumProjectedPixels = 1; // default 0.5
scene.paint(canvas, size);
debugPrint('drawn ${scene.stats.drawn} / culled ${scene.stats.culled}');
```

## Slice LOD

A stack is a pile of cross-sections `spacing` apart. Once a prop is drawn small
enough that consecutive slices land under a device pixel, the downscale merges
them anyway — so `scene.sliceLod` (on by default) draws every `N`th slice for
those props. Each drawn slice stays at its true height, so the silhouette does
not move; only sections that could not be told apart stop costing a rasterizer
pass.

The rule is geometric: drawn slices stay at most `sliceLodPixels` device pixels
apart (default `1`). At `scale: 0.25` with `spacing: 1` four slices share a
pixel, so three of every four are skipped.

```dart
scene.sliceLod = true;        // default
scene.sliceLodPixels = 1;     // conservative; raise it to decimate harder
scene.objects[3].sliceStep = 2; // or force a step for one prop
```

`scene.stats.slicesDrawn` / `slicesTotal` (and `sliceLodSaving`) report what the
frame selected:

```dart
scene.paint(canvas, size);
debugPrint('slices ${scene.stats.slicesDrawn}/${scene.stats.slicesTotal} '
    '(${(scene.stats.sliceLodSaving * 100).round()}% saved)');
```

Set `sliceLod = false`, or use `SpriteStackSceneObject.sliceStep = 1`, when you
want every cross-section regardless of distance.

## Banking an aircraft

`roll` is a **render** parameter, like `pitch` — it is not part of the scene. It
tilts the finished sprite in screen space around a pivot `rollPivot` of the way
up the body (`0` = feet planted, `0.5` = body middle):

```dart
// bank into the turn: derive the target from the yaw rate
final targetRoll = (turnRate * 0.6).clamp(-0.85, 0.85);
final f = SpriteStackFollowCamera.smoothing(8, dt);
bank = SpriteStackFollowCamera.approachAngle(bank, targetRoll, f);
object.roll = bank;
object.rollPivot = 0.45;
```

`roll` rotates the silhouette without revealing a new side of the prop — for
that, turn `yaw`. `boundsFor` returns the rotated envelope, so culling stays
exact while the aircraft banks. A flying prop usually wants `shadow: false`.
